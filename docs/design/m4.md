# M4 — Combat drops (roadmap 7.5)

Two parallel packages on top of M3 (docs/design/m3.md). Merge order: B
(bridge + drivers) first, then A (data + hunt run). CielCraft never casts a
combat action itself: a combat plugin drives the fight over IPC; the hunt
run only travels, targets, engages / disengages, verifies drops and keeps
the character safe. Hunting is opt-in (`HuntingEnabled`, default off) and
the source offers nothing when no combat plugin is loaded.

## Contract (already on main)

- `Core/Combat/CombatContracts.cs`: `CombatDriverKind` (None /
  RotationSolverReborn / BossModReborn), `ICombatDriver` (Kind, Name,
  IsAvailable, Engage, Disengage, IsEngaged, Describe), `MobDrop(ItemId,
  BNpcNameId, MobName, Level, TerritoryId, ZoneName, Position?)`,
  `IHuntSpots` (DropsOf(itemId) best first, RememberSpot).
- `AutomationSettings` M4 block: `HuntingEnabled`, `CombatJobId` (0 = the
  highest-level combat job with a gearset), `HuntRetreatHpPercent`,
  `HuntMaxLevelAbove`, `HuntSkipMobsTargetedByOthers`.
- The M3 source contract (`IMaterialSource`, `ISourceRun`, the runner's
  `RunningSource` phase) and NPC / travel seams (`TravelDriver`,
  `INpcInteractor`) — see m3.md.
- Verified facts (2026-09-15, from the plugins' sources): Rotation Solver
  Reborn registers IPC under the prefix `RotationSolverReborn.` with
  `ChangeOperatingMode(StateCommandType)` (Off / Auto / Manual — read the
  enum values from the repository, they are ints over IPC),
  `AutodutyChangeOperatingMode(StateCommandType, TargetingType)`,
  `Add/RemovePriorityNameID(uint)`, `Add/RemoveBlacklistNameID(uint)`,
  `AutorotationActive() → bool`, `Test(string)`. BossMod Reborn registers
  `BossMod.Presets.SetActive(string) → bool`, `Presets.ClearActive() → bool`,
  `Presets.GetActive() → string`, `Presets.SetForceDisabled() → bool`,
  `AI.SetPreset(string)`, `AI.PauseMovement(bool)`, `Rotation.ActionQueue
  .HasEntries() → bool`, `Configuration(List<string>, bool)` (console
  commands, e.g. to turn AI on/off) among many more. Neither plugin is
  installed on the test machine today, so every IPC call must be guarded
  by `IsAvailable` and fail soft.
- Garland Tools (verified): `https://garlandtools.org/db/doc/browse/en/2/mob.json`
  lists every mob as `{"i":20000000002,"n":"Ruins Runner","l":"50","z":404}`;
  `https://garlandtools.org/db/doc/mob/en/2/<id>.json` gives
  `{"name","id","zoneid","lvl","drops":[itemIds…]}` (no coordinates);
  `https://garlandtools.org/db/doc/core/en/3/data.json` has the location
  index that maps Garland zone ids to place names (match them to
  `TerritoryType` through `PlaceName`). Mob ids are `20000000000 + BNpcName
  row` (check on a few rows; if not, keep Garland's own ids and map by name
  through the `BNpcName` sheet).

## A — Drop data, combat database, hunt run (owns new `tools/refresh-drops.ps1`, new `CielCraft/Data/drops.json` (bundled, copied to the output like the gathering data is — check the csproj for the pattern), new `Game/CombatDatabase.cs`, new `Sourcing/CombatSource.cs`, new `Combat/HuntRun.cs`, new `CielCraft.Tests/HuntRunTests.cs`, `CielCraft.csproj` only for the data file)

1. **Refresh script** (PowerShell, no build dependency): download the mob
   index, then each mob doc (throttled, resumable, cached under
   `%LOCALAPPDATA%\CielCraft\garland\`), the core data for the zone index;
   write `drops.json` as `[{ "item": id, "mobs": [{ "bnpc": id, "name":
   "...", "level": n, "zone": "place name", "territory": id? }] }]` for
   items that are craft ingredients only (filter with the Recipe sheet
   ingredient set if the script can read it — otherwise keep every
   dropped item; size matters, say what you did). Commit the generated
   file; the script is for refreshes after patches.
2. **Combat database** (`CombatDatabase : IHuntSpots`): loads the bundled
   file, resolves zone names → `TerritoryType` via `PlaceName`, mob names →
   `BNpcName` rows, keeps remembered spots in the configuration (add
   `HuntSpots` to `AutomationSettings` in your own block at the end) and
   ranks: remembered spot first, then the lowest-level mob in a zone with
   an attuned aetheryte (bridge `CanTeleportTo`), then any. `Map` sheet
   bounds per territory for the sweep. `Describe()`.
3. **Source** (`CombatSource : IMaterialSource`, Kind — add
   `MaterialSourceKind.Hunt` to the Core enum, it is additive) offers when
   `HuntingEnabled`, a driver `IsAvailable`, the item has a mob whose level
   fits the chosen combat job (`CombatJobId` or the best job with a gearset
   — `CharacterCapabilities.JobLevels` will carry combat jobs after B
   lands; until then use `LevelOf` and treat 0 as unknown = allowed) and
   `HuntMaxLevelAbove`. Description "Hunt Raptor Skin ×5 from Raptors
   (Coerthas Central Highlands, Lv 30)".
4. **Hunt run** (`HuntRun : AutomationMachine<…>, ISourceRun`, prefix
   `[Hunt]`): gearset (`EquipGearsetForJob`), teleport / travel to the spot
   (or a zone sweep along a coarse grid over the map bounds, flying when
   allowed, until the bridge sees the mob), pick a target (bridge
   `FindHuntTargets` from B: nearest of the name, alive, not another
   player's, level ≤ own + `HuntMaxLevelAbove`), `TargetObject`, move into
   range (`TravelDriver`, arrive within ~3y for melee / 20y ranged — take
   the job's range from a small table), `driver.Engage()`, wait for the
   kill (target gone / dead) with a per-target timeout, count the drop by
   inventory delta, `driver.Disengage()`, settle, next target until the
   amount is reached. Safety: retreat when HP < `HuntRetreatHpPercent`
   (disengage, run to the last safe point, wait to regen), death (bridge
   `IsDead` → answer the Return prompt, wait for the revive, resume from the
   aetheryte once, then fail), "someone else is here" (skip mobs targeted
   by others when the setting says so), too many failures → Failed with
   the reason. Pause / Resume / Stop always disengage. `Describe()`.
5. Tests: the database ranking and the run's state flow against a fake
   bridge and a fake driver (engage/disengage counts, retreat, death,
   completion by delta).

## B — Bridge combat members, drivers, job levels (owns bridge members under `// ---- Combat (7.5) ----` at the end of `IGameBridge` / `DalamudGameBridge` + FakeBridge stubs, new `Combat/CombatDrivers.cs` (RSR + BMR adapters and a `CombatDriverSelector`), `Game/CapabilityReader.cs` (job levels for every job), new `Windows/HuntPanel.cs`, new `CielCraft.Tests/CombatDriverTests.cs`)

1. **Bridge**: `FindHuntTargets(bnpcNameId, excluded, origin?) →
   IReadOnlyList<HuntTargetSnapshot>` (object id, name, level, position,
   distance, HP %, `TargetedByOthers`, `IsAlive`) over `ObjectTable`
   battle NPCs (`BattleNpc`, `NameId`, `BattleNpcKind.Enemy`), `TargetObject
   (objectId)`, `CurrentTargetId`, `PlayerHpPercent`, `IsInCombat`
   (`ConditionFlag.InCombat`), `IsDead` (`LocalPlayer.IsDead` /
   `ConditionFlag.Unconscious`), `AnswerReturnPrompt()` (the death
   SelectYesno / `/return` when no raise), `EnemiesTargetingMe()` count.
2. **Drivers**: `RotationSolverDriver` and `BossModDriver` over
   `PluginInterface.GetIpcSubscriber` (the names above; RSR: Auto on
   Engage, Off on Disengage; BMR: activate a named preset or the AI via the
   console command, clear on Disengage — say which you chose and why), each
   `IsAvailable` = installed + loaded (`PluginInterface.InstalledPlugins`)
   + the IPC answers; `CombatDriverSelector` picks RSR first, then BMR,
   else a `NoCombatDriver` whose `IsAvailable` is false. A `Test` /
   `AutorotationActive` probe in `Describe()`.
3. **Job levels**: `CapabilityReader` reads every ClassJob level (combat
   jobs included) into `JobLevels`; `CharacterCapabilities.BestCombatJob
   (hasGearset)` helper in Core (additive).
4. **Panel** (`HuntPanel.Draw()`, Tools › Hunting; the coordinator wires
   it): driver status, the hunt run's state, a "remember this spot for
   <item>" button (calls `IHuntSpots.RememberSpot` with the player
   position — take an `IHuntSpots?` that the coordinator sets after A
   lands, null until then), and the M4 settings (`DrawSettings
   (Configuration)` for the Sourcing page).
5. Tests: driver selection with fake availability, the Engage/Disengage
   bookkeeping, the target ranking helper if you keep it in Core.
