# M3 — Beyond gather and craft: NPCs, vendors, exchanges, retainers, fishing

Five parallel packages on top of M2 (docs/design/m2.md, orders.md, m1.md).
7.19 (equipment set builder) is skipped for now. Merge order: P1 (NPC layer)
first — everything else travels through it; then P2, P3a, P3b, P4. The
coordinator wires `Plugin.cs`, `MainWindow` / `SettingsPanel` and any
runner one-liners listed under "coordinator".

## Contract (already on main)

- **Sources.** `Core/Sourcing/MaterialSources.cs`: `MaterialSourceKind`
  (Gather / Buy / Exchange / Fish / Retainer), `SourceOffer(ItemId, Amount,
  Kind, Description, EstimatedSeconds, GilCost)`, `ISourceRun` (State
  Idle/Running/Paused/Completed/Failed, StatusText, Obtained, Tick, Pause,
  Resume, Stop, Describe) and `IMaterialSource` (Kind, Name, `Offer(itemId,
  amount)`, `Start(offer) → ISourceRun`). The production runner already
  asks its registered sources, in order, for every raw material no MIN/BTN
  node yields, starts the offered run as a queue task, ticks it in a
  `RunningSource` phase, forwards pause / resume / stop, and finishes it
  like a gather task (`ProductionRunner`, "M3" comments). A source run owns
  its own travel (use `TravelDriver` / the NPC interactor), dialogs and
  verification; the bag count is the truth. Register sources in
  `Plugin.cs` (coordinator): `new ProductionRunner(..., sources: [...])`.
  With `AutomationSettings.BuyWhenGatherable` the vendor source should also
  be preferred for gatherable items — that ordering change in
  `BuildGatherTasks` is a coordinator one-liner once P2 lands; do not edit
  the runner.
- **NPCs.** `Core/Npc/NpcInteraction.cs`: `NpcTarget(NpcId, Name,
  TerritoryId, Position, DataId)`, `INpcLocator.Locate(npcId)`, the dialog
  steps (`SelectOption(textContains)`, `AdvanceTalk`, `Confirm(yes)`,
  `WaitForAddon(name)`), `NpcInteractionState` and `INpcInteractor`
  (`Start(target, script, description)`, Tick, Pause, Resume, Stop,
  StatusText, FailureReason, Describe). P1 implements both; P2, P3a and P4
  take an `INpcInteractor` and an `INpcLocator` in their constructors and
  never construct P1's classes.
- **Settings** (`AutomationSettings`, M3 block): `GilFloor`,
  `GilSpendCapPerRun`, `BuyWhenGatherable`, `MenderRepair`,
  `ScripSourcePreference` (Cheapest / Fastest), `DesynthUnusedByproducts`,
  `TrashCleanup`, `RetainerVentures`, `FishingPreferAutoHook`. Add more only
  in your own block at the end of the file and say so in the report.
- **Bridge.** `IGameBridge` already has `IsAddonVisible`,
  `FireAddonCallbackInt`, `ReadAddonStrings`, `InteractWithObject`,
  `TeleportToTerritory`, `GetItemCount`, `GetFreeInventorySlots`,
  `ExecuteChatCommand`. Each package appends its own members at the **end**
  of `IGameBridge` and `DalamudGameBridge` under a `// ---- <package> ----`
  banner, and adds throwing stubs for them to the `FakeBridge` in
  `CielCraft.Tests/MaintenanceTests.cs` (the coordinator merges the
  banners). Never edit another package's bridge members.
- **Seams to reuse.** `AutomationMachine<TState>`, `Throttle`, `IClock`,
  `ILog`, `TravelDriver` (mount / fly / land / walk-up, `preciseArrival`),
  `Pacing` (settle delays — keep them), `MaintenanceService` phase pattern
  (repair: open window, callback, SelectYesno, verify, timeout, non-fatal),
  `GatheringDatabase` (sheet indexing pattern, `Plugin.DataManager`),
  `CharacterCapabilities`, `OrderPlanner` / `DependencyResolver`.
- **Sheet / struct exploration.** The console project at
  `%LOCALAPPDATA%\Temp\claude\C--dev-cielcraft\10556bcc-14c0-48cb-8838-8e5af65d3afa\scratchpad\reflect`
  (copy it to your own scratch folder) loads Lumina sheets from the game
  install and dumps ClientStructs / Dalamud types from
  `%APPDATA%\XIVLauncher\addon\Hooks\dev`. Never guess ids, callback
  values or column names: read them from the sheets / types, or cite the
  open-source plugin you took them from (Artisan, ECommons, AutoRetainer,

## P1 — NPC interaction layer + mender repair (7.3, 7.3a) — owns new `Game/NpcDatabase.cs`, new `Npc/NpcInteractor.cs`, `Game/MaintenanceService.cs`, bridge members under `// ---- NPC (7.3) ----`, new `CielCraft.Tests/NpcInteractorTests.cs`

1. **NPC database** (`NpcDatabase : INpcLocator`): `ENpcResident` (name)
   + `Level` sheet rows of type ENpc (`Level.Object` = the ENpcBase row,
   `Territory`, X/Y/Z) → `NpcTarget`; `Locate(npcId)`; `FindMenders()` →
   the NPCs whose `ENpcBase.ENpcData` contains the repair event handler id
   range (the "Mender" title in `ENpcResident.Title` is the fallback —
   say which you used); `NearestMender(territoryId, position)` preferring
   the current zone, then any zone with an attuned aetheryte. Cache per
   session.
2. **Interactor** (`NpcInteractor : AutomationMachine<NpcInteractionState>,
   INpcInteractor`): teleport when the territory differs
   (`TeleportToTerritory`; wait for the loading screen like the runner's
   `TickTeleporting`), `TravelDriver` to the position (fly when the
   capabilities allow, `preciseArrival: true`, arrive within ~3y), find
   the object by `DataId` (bridge: `FindNpcObject(dataId) → (objectId,
   position)?` — the object table, `ObjectKind.EventNpc`), target and
   `InteractWithObject`, then the script: `SelectString` /
   `SelectIconString` by option text (bridge: `SelectDialogOption(text)`
   reading the addon's strings; fire the index), `Talk` advance (bridge:
   `AdvanceTalk()`), `SelectYesno`, `WaitForAddon`. Timeouts per step
   (10 s), the same interference rule as travel (manual movement = user
   took over → Paused), `Stop` closes an open Talk / SelectString /
   SelectYesno. `Describe()` for the report.
3. **Mender repair** (7.3a) in `MaintenanceService`: when self-repair
   finds no Dark Matter and `MenderRepair` is on, instead of
   `BlockedReason`, start an interaction with the nearest mender (script:
   `SelectOption("Repair")` → `WaitForAddon("Repair")`), then the existing
   repair-all phases against the mender's Repair window (callback 0 +
   SelectYesno, verified by condition), close, and return to where the
   run was (the runner / loop resumes by itself — the maintenance tick
   simply reports busy until done; if the previous task needs the
   previous position, say so in the report and leave the return trip to
   the caller). No mender reachable → the existing `BlockedReason`.
   `MaintenanceService` gets optional ctor params `INpcInteractor? npc,
   NpcDatabase? npcs` (null = today's behaviour) — the coordinator passes
   them.
4. Tests: the interactor against a scripted fake bridge / navigation
   (teleport → travel → interact → script → completed; a step timing out →
   Failed with the reason; Stop closes the dialog).

## P2 — Vendor purchases (7.3b) — owns new `Game/ShopDatabase.cs`, new `Sourcing/VendorSource.cs`, bridge members under `// ---- Shops (7.3b) ----`, `Windows/PlanTreePanel.cs` + `Core/Planning/PlanTree.cs` (source labels on raw-material nodes), new `CielCraft.Tests/VendorSourceTests.cs`

1. **Shop database**: `GilShopItem` (item → GilShop) + the NPCs whose
   `ENpcBase.ENpcData` references that GilShop → `(ItemId, Price, ShopId,
   NpcId)`; `FindVendors(itemId)` ordered by "current zone first, then any
   zone with an attuned aetheryte, then cheapest"; special / currency
   shops (`SpecialShop`, `GCShop`) excluded here (P3a). Price from
   `Item.PriceMid`. Names for the log.
2. **Source** (`VendorSource : IMaterialSource`, Kind Buy, Name "vendor"):
   `Offer` when a vendor is known, the character can reach it (locator +
   attuned aetheryte in that territory — bridge: the existing teleport
   list check; expose `CanTeleportTo(territoryId)` if needed) and the gil
   works: `price × amount ≤ min(gil − GilFloor, GilSpendCapPerRun − spent
   this run)` (bridge: `Gil` property; the run-spend counter lives in the
   source and resets when the runner starts — add a `ResetRunBudget()`
   the coordinator calls from `ProductionRunner.Start`, or reset when a
   new offer sequence begins; say which). Description: "Buy 5× Iron Ore
   from Smyth (Ul'dah, 120 gil)". `Start` → a `VendorRun : ISourceRun`:
   NPC interactor to the vendor with script `SelectOption("Purchase")`
   (the exact option text per shop type — check the SelectIconString
   labels; many vendors open the Shop addon directly) → `WaitForAddon
   ("Shop")`, then buy: bridge `BuyFromShop(itemId, count)` (Shop addon
   callback — AgentShop / `ShopEventHandler.BuyItemFromShop` per
   ClientStructs; cite what you use), verify by inventory delta, close the
   shop (`CloseShop()`), Completed. Stack limits and bag space (buy in
   batches of ≤ 99; free slots).
3. **Planner surface**: `PlanTree` raw-material nodes take an optional
   `Func<uint, string?> sourceLabel` (the coordinator passes a lambda over
   the registered sources' `Offer`) and show "buy from <vendor>" instead
   of the zone; `/cielcraft plan` and the report inherit it.
4. Tests: the offer maths (floor, cap, price), vendor ordering, the run's
   state flow against a fake interactor / bridge.

## P3a — Exchanges + collectables-for-scrips planner (7.17 part 1) — owns new `Game/ExchangeDatabase.cs`, new `Sourcing/ExchangeSource.cs`, new `Core/Sourcing/ScripPlanner.cs`, bridge members under `// ---- Exchanges (7.17) ----`, new `CielCraft.Tests/ScripPlannerTests.cs`

1. **Exchange database**: `SpecialShop` (item ← currency: scrips,
   tomestones, other items) and `GCScripShopItem` / `GCShop` (Grand
   Company seals) → `(ItemId, CurrencyItemId, Cost, ShopId, NpcId)`;
   currencies are items (scrips 33913/33914/41784… — read from the
   sheets, do not hard-code), seals via `GrandCompany` rank. Vendors per
   shop as in P2 (`ENpcBase.ENpcData` → SpecialShop id).
2. **Source** (`ExchangeSource : IMaterialSource`, Kind Exchange, Name
   "exchange"): offer when the character holds enough currency (bridge:
   `GetCurrencyCount(itemId)` — currencies live in the Currency container;
   GC seals via `InventoryManager.GetGrandCompanySeals` or the currency
   items) and the NPC is reachable; the run: interactor →
   `WaitForAddon("ShopExchangeCurrency")` (or the shop's addon — check
   which one each `SpecialShop` opens), bridge `ExchangeBuy(shopId, itemId,
   count)` (AgentShopExchangeCurrency / the addon callback; cite), verify
   by delta, close.
3. **Scrip planner** (Core, pure): given the scrips an order needs
   (`ScripNeed(currencyItemId, amount)`), the turn-ins available
   (`CollectablesShopItem` rows for the character's level: item, tier
   thresholds, scrip reward per tier — the plugin builds these from the
   sheets and hands them over) and the crafter / gatherer levels, choose
   the turn-ins that earn the scrips: `Cheapest` = fewest materials per
   scrip (crafted collectables at the lowest tier that pays, gathered
   collectables at the cheapest node), `Fastest` = fewest trips; output
   `ScripPlan` = a list of `PlanTarget`s (collectable craft / gather
   orders at a tier) plus the turn-in NPC. The exchange source exposes
   `MissingCurrency(itemId, amount) → ScripNeed?` so the order runner can
   (later, coordinator) prepend the scrip plan's targets to a group that
   needs an exchange item; for now a Tools › Scrips page is not required —
   the planner is Core + tests, the turn-in run (`CollectablesShop` addon:
   bridge `TurnInCollectable(itemId)` + `HandInTurnIn`) is implemented as
   an `ISourceRun` the exchange source can chain before buying when the
   currency is short and the collectables are already in the bag.
4. Tests: the planner (cheapest vs fastest, level gating, tiers), the
   offer maths, the run flow with fakes.
